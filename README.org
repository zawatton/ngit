#+TITLE: ngit — Git implemented in NeLisp
#+OPTIONS: toc:2

ngit is a Git implementation written in Emacs Lisp for the standalone
[[https://github.com/zawatton/nelisp][NeLisp runtime]].
It reads and writes Git's repository format: objects, refs, index and worktree.
Use it alongside Git in an existing SHA-1 repository without converting
or importing your history.

ngit is under active development. Supported cases are compared with Git for
output and repository state; a supported command does not imply complete
Git compatibility. Keep Git available for unsupported operations.
The native implementation supports *Linux x86_64* and has a
[[file:docs/windows.org][Windows x86-64 backend validated with Wine]].

* Install
:PROPERTIES:
:CUSTOM_ID: install
:END:

** Requirements

| Component | Requirement |
|-----------+-------------|
| OS / CPU | Linux x86_64; see the separate Windows setup for Windows x86-64 |
| Runtime | A compatible standalone NeLisp binary and its =packages/nl-ffi= source |
| Libraries | zlib =libz.so.1= and OpenSSL 3 =libcrypto.so.3= |
| HTTPS | libcurl =libcurl.so.4= with its TLS backend and CA certificates |
| Transport supervisor | Python 3 for clone, fetch and pull |
| SSH remotes | OpenSSH client and a working key/agent configuration |
| Build tools | Git, POSIX shell, make and GNU Emacs 30.2 or newer |

Emacs builds NeLisp and optionally compiles ngit's Lisp files. Normal ngit
commands run in the standalone NeLisp process. Local/file remotes also use
Git's =git-upload-pack= / =git-receive-pack= executables; keep Git installed.
Install the tools and libraries with your distribution's package manager.
Check the Emacs version; older distribution packages may not meet the
runtime build requirement.

#+begin_src sh
uname -sm
emacs --version
git --version
python3 --version
#+end_src

** Build NeLisp and install ngit

Keep the two repositories next to each other. The NeLisp commit below
identifies the runtime used for the 2026-10-28 ngit validation; compatibility
with older release tags is not established. Building this source snapshot
is separate from ngit's optional byte compilation.

#+begin_src sh
mkdir -p "$HOME/src"
git clone https://github.com/zawatton/nelisp.git "$HOME/src/nelisp"
git -C "$HOME/src/nelisp" checkout a14b1a2e4dc81b975135e73c8763821cb3484354
(
    cd "$HOME/src/nelisp"
    ulimit -v 8388608
    make standalone-reader
)

git clone https://github.com/zawatton/ngit.git "$HOME/src/ngit"
cd "$HOME/src/ngit"

export NGIT_NELISP="$HOME/src/nelisp/target/nelisp"
export NGIT_NELISP_ROOT="$HOME/src/nelisp"
export PATH="$HOME/src/ngit/bin:$PATH"

# Recommended: compile ngit's Lisp modules for faster startup.
(ulimit -v 8388608; sh tools/build-elc.sh)
command -v ngit
#+end_src

Add the three =export= lines to your shell's startup file, such as
=~/.bashrc= or =~/.zshrc=, to keep them in new terminals.
Keep both checkouts; copying only =bin/ngit= does not install its Lisp modules.
Add the original =bin= directory to =PATH=: a symlink to the launcher does
not preserve its relative module lookup.

** Use an existing NeLisp installation

Skip the NeLisp clone/build steps if you already have a compatible binary and
matching source tree. Set these variables for your installation:

#+begin_src sh
export NGIT_NELISP="/path/to/nelisp"
export NGIT_NELISP_ROOT="/path/to/nelisp-checkout"
export PATH="$HOME/src/ngit/bin:$PATH"
#+end_src

=NGIT_NELISP= names one executable, without arguments; if unset, ngit uses
=nelisp= from =PATH=. =NGIT_NELISP_ROOT= must contain
=packages/nl-ffi/src/nl-ffi.el= and =nl-ffi-memory.el=; if unset, ngit looks for
a sibling =nelisp= checkout. An existing native NeLisp build can be used here;
ngit does not require a separate native build of its own.

* Create your first repository
:PROPERTIES:
:CUSTOM_ID: create-your-first-repository
:END:

Use a new directory and replace the example identity with yours.

#+begin_src sh
ngit init -b main "$HOME/src/ngit-demo"
cd "$HOME/src/ngit-demo"
ngit config user.name "Your Name"
ngit config user.email "you@example.com"

printf 'Hello from ngit\n' > hello.txt
ngit status --short
ngit add hello.txt
ngit commit -m "Add hello"
ngit log --oneline -1

# Git reads the same commit and repository.
git log --oneline -1
git fsck --no-dangling
#+end_src

* Switch from Git
:PROPERTIES:
:CUSTOM_ID: switch-from-git
:END:

** 1. Check your repository and workflow

Start with an ordinary SHA-1 repository and finish any merge, rebase or
cherry-pick already in progress.

#+begin_src sh
cd /path/to/your/project
git rev-parse --show-object-format
git status --short
git remote -v
#+end_src

Check [[#compatibility-limits][the compatibility limits]], particularly Git LFS and other
clean filters, submodules, sparse checkouts, interactive staging/rebase and
signed commits. Existing system, global and repository configuration is read;
there is no separate ngit identity or remote database. Only implemented
configuration settings affect behavior.

** 2. Compare inspection commands

Use the same repository with both commands. No reinitialization or reclone
is needed; branches, history, remotes and the index remain in place.

#+begin_src sh
git status --porcelain
ngit status --porcelain
git log --oneline -5
ngit log --oneline -5
git diff --stat
ngit diff --stat
#+end_src

For a separate trial, =git clone /path/to/project /path/to/trial= copies
committed history; it does not carry uncommitted work or every local setting.
Try writes there first if you prefer.

** 3. Use ngit for supported operations

#+begin_src sh
ngit switch -c try-ngit
# Edit a file in your editor, then use its actual path below.
ngit diff -- path/to/file
ngit add path/to/file
ngit diff --cached
ngit commit -m "Describe the change"
ngit log --oneline -5
#+end_src

Alternate Git and ngit in the same repository, finishing one command before
starting another write. Invoke Git explicitly for unsupported operations,
for example =git add -p=, =git rebase -i= or =git commit -S=.

** 4. Keep command selection explicit and return to Git when needed

Use =ngit= for ngit and =git= for Git while checking compatibility.
Avoid a global =alias git=ngit=: hooks, helpers, IDEs and scripts may invoke
options that ngit does not implement. Keep editor integrations on Git until
their exact command set has been checked.

To return to Git, use =git= again. No reverse migration or repository cleanup
is needed. To stop using the installation, remove ngit's =PATH= entry and the
=NGIT_NELISP= / =NGIT_NELISP_ROOT= exports from your shell configuration.

* Daily commands
:PROPERTIES:
:CUSTOM_ID: daily-commands
:END:

| Task | Command |
|------+---------|
| Inspect changes | =ngit status --short= |
| Inspect unstaged changes | =ngit diff -- path/to/file= |
| Inspect staged changes | =ngit diff --cached= |
| Stage files | =ngit add path/to/file= |
| Commit | =ngit commit -m "Message"= |
| View recent history | =ngit log --oneline -10= |
| Create and switch branch | =ngit switch -c feature= |
| Switch branch | =ngit switch main= |
| Restore an unstaged file | =ngit restore -- path/to/file= |
| Unstage, keeping worktree content | =ngit restore --staged -- path/to/file= |
| Stash work | =ngit stash push -m "Work in progress"= |
| Reapply a stash | =ngit stash pop= |
| Inspect remotes | =ngit remote -v= |

=restore= overwrites the selected unstaged content; inspect =diff= first.
See the [[file:docs/command-reference.org][command reference]] for supported options and pathspecs.

* Remotes and authentication
:PROPERTIES:
:CUSTOM_ID: remotes-and-authentication
:END:

Existing remotes are shared with Git. For a new repository, add your own URL:

#+begin_src sh
ngit remote add origin git@github.com:YOUR_ACCOUNT/YOUR_REPOSITORY.git
ngit push -u origin main
ngit fetch origin
ngit pull --rebase
#+end_src

Use =ngit remote set-url origin URL= if =origin= exists.
SSH uses your SSH configuration and =GIT_SSH_COMMAND= / =core.sshCommand=.
Set up your SSH key or agent before using an SSH remote.

HTTPS supports noninteractive Basic credentials, Git-style credential helpers
and =http.extraHeader=. Use a helper that can return credentials without
a prompt. Interactive password/token prompts and OAuth login flows are not
implemented. Keep tokens out of remote URLs and shell history.
Certificate verification is enabled; =GIT_SSL_CAINFO= or =http.sslCAInfo=
can select a private CA.

=clone=, =fetch= and =pull= start the Python memory supervisor with an
8192 MiB budget. =NGIT_MEMORY_BUDGET_MIB= overrides it and also enables
supervision for other commands. This sampled process-tree budget is not a
hard allocation ceiling. See the [[file:docs/command-reference.org][transport reference]].

* Performance and editor integration
:PROPERTIES:
:CUSTOM_ID: performance-and-editor-integration
:END:

Rerun =sh tools/build-elc.sh= after updating ngit to reduce startup overhead.
Stale bytecode is ignored and execution falls back to source;
=NGIT_NO_ELC=1= explicitly selects source.

Ordinary one-shot ngit commands still have much higher startup costs than Git.
The experimental =status-server= keeps one process open for repeated editor
queries. In the 2026-10-28 local 1,201-file fixture, resident medians were
about 2.52 ms for different-size edits, 2.68 ms for same-size edits and
1.80 ms for unchanged requests; Git was about 2.85–2.86 ms.
The first startup/status took about 5.74 seconds. These are fixture-specific
resident round trips, not a claim that the ordinary ngit CLI is faster.

#+begin_src sh
ngit -C /path/to/project status-server
#+end_src

Send =status=, =refresh=, =stats= or =quit= as ASCII lines.
Replies use =OK BYTE_COUNT\n= or =ERR EXIT_CODE BYTE_COUNT\n= followed by
exactly that many payload bytes. This opt-in integration protocol is not a
replacement executable for editor settings that expect Git.
Only certified dependencies permit cached/incremental reuse; inspect
=cache_enabled= and =cache_reason= in =stats=. Use =refresh= after mmap writes,
remote writes or mount replacement.
See [[file:docs/status-session.org][the API and filesystem limits]] and
[[file:docs/status-config-cache.org][the configuration cache and benchmark method]].

* Troubleshooting
:PROPERTIES:
:CUSTOM_ID: troubleshooting
:END:

| Symptom | Check |
|---------+-------|
| =ngit: command not found= | Add the original checkout's =bin= directory to =PATH= and open a new shell |
| =nelisp: not found= | Set =NGIT_NELISP= to an executable or put =nelisp= on =PATH= |
| Cannot load =nl-ffi.el= | Set =NGIT_NELISP_ROOT= to the checkout containing =packages/nl-ffi/src= |
| Missing library / symbol | Check the required SONAMEs and the runtime/source pairing |
| Emacs not found during byte compilation | Set =EMACS= to the host executable; otherwise ngit runs from source |
| Unexpected behavior after an update | Rebuild bytecode and verify the selected NeLisp binary and sources |
| HTTPS authentication fails | Check the noninteractive helper and its =PATH= / =GIT_EXEC_PATH= dependencies |
| Cached status is unavailable | Read =stats=; unsupported dependencies force fresh reads or an explicit error |

For a report, include OS/architecture, ngit commit
(=git -C "$HOME/src/ngit" rev-parse HEAD=), NeLisp build identity, command,
exit status and a small reproducer. Remove credentials and private data.

* Compatibility limits
:PROPERTIES:
:CUSTOM_ID: compatibility-limits
:END:

Dumb HTTP, interactive credential prompts, OAuth and git:// transports,
protocol-v2 shallow/partial fetch, packfile-uris, bundle-uri and object-info,
shallow/partial clones,
template copying, =--force-if-includes= pushes,
push.default=matching/nothing, multi-head pulls, submodules (beyond
gitlink entries), strategy-specific
rename thresholds, octopus merges, custom merge
drivers, rebase --exec, interactive rebase (and its hooks) and
merge-preserving rebase (pull refuses rebase=merges on diverged histories and
rebase=interactive unless HEAD is up to date or fast-forwards, before
installing fetched objects or updating any ref), rerere, =--fix-thin=, git's delta search depth
(new deltas are limited to 4 KiB targets and 32 KiB per run; pack
compression defaults to level 1), blame -M/-C, grep -P, name-rev --all,
general MIME mail in am/apply, traditional (non-git) patches
whose body lines look like a =+++= header line,
delta-encoded binary hunks in output (format-patch always writes
=literal= binary bodies where Git picks the smaller of delta and literal;
apply and am read both forms).

Global options other than -c, -C, --config-env, -P/--no-pager/-p/--paginate,
--git-dir, --work-tree and --bare (the last three only set GIT_DIR and
GIT_WORK_TREE; status and rev-parse under them can differ from Git), and git
config value patterns and --replace-all/--unset-all on multi-valued variables.

Alternates, multi-pack-index, reftable, split or sparse
indexes, SHA-256 repositories, copy detection, commit
signing, index.version for new indexes,
custom attribute macros and diff drivers, subdirectory path handling
outside status/diff/add/restore/log/show/grep/blame/ls-tree/ls-files/clean/
rm/mv/checkout/reset/stash, log -L, notes, tag signing, reset -p,
checkout/switch -p and sparse checkouts, restore -p, rm/mv --sparse,
stash -p, add -p/-i/--patch (rejected as unsupported options).

apply and am still differ from Git on: stash push --staged of a file whose
name contains a byte that is not valid UTF-8 (ngit saves the stash, then
fails to read the name back and keeps the change), and apply --index over
an intent-to-add entry marked valid by an fsmonitor enabled only through
GIT_TEST_FSMONITOR; =sh test/apply-gen.sh deferred= carries them as failing
cases d5-disc-1 and d5-deferred-1.

Relative local clone URLs containing =..= can produce different path spellings
in =remote.origin.url= and clone reflogs: Git preserves the lexical path,
while ngit records the normalized absolute path. These pre-existing differences
remain executable in =python3 test/h-transport.py deferred=.
