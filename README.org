#+TITLE: ngit — git implemented in NeLisp

A git implementation (object store, refs, index and work tree inspection,
plus add, commit, log, show, branch, tag, reset, switch, checkout, rm, mv,
restore, stash, merge, cherry-pick, revert, rebase, packs and maintenance,
fsck, clone/fetch/pull/push over local, file:// and ssh remotes, blame,
grep, describe, format-patch/apply/am, clean, worktree, config and bisect)
that runs on the NeLisp standalone runtime (=nelisp=).  Output is byte-identical to git for the supported
commands, verified by =test/compare.sh= against real git.

=bin/ngit= passes each argument with an "@" prefix because the NeLisp
runtime drops =-q=, =-Q=, =--batch= and =--no-init-file= even after =--=.

=NGIT_NELISP= selects the runtime binary (default =nelisp= on PATH) and
=NGIT_NELISP_ROOT= the NeLisp checkout providing =packages/nl-ffi=
(default: =../nelisp= next to this repository).

Status, diff, add and restore accept literal paths relative to the invocation
directory, including repeated =-C=. Human status paths follow
=status.relativePaths=; porcelain status and default diff paths remain
relative to the work-tree root. Diff path arguments require =--=.

Log, show, grep, blame and ls-tree also resolve literal path arguments from
the invocation directory. Log keeps its existing glob support and remains
repository-wide without paths; grep defaults to the invocation subtree.
Blame's porcelain paths and history diff paths remain root-relative.
Ls-tree's =--full-name= changes displayed names; =--full-tree= also selects
from the tree root. Ordinary =REV:path= object names remain tree-relative,
while =REV:./path= and =REV:../path= use the invocation directory.

Push supports explicit and tracking-based =--force-with-lease= expectations
and receive-pack =--atomic= negotiation over the existing local/file/SSH
transports. As in the Git 2.47.3 comparison oracle, explicit =--force= or a
forced refspec overrides a lease. =--atomic= fails if the peer does not
advertise the capability.

Clone, fetch and pull use a Linux/Python 3 process supervisor with an
8192 MiB aggregate memory budget. Set =NGIT_MEMORY_BUDGET_MIB= to a positive
integer to change it; setting it also enables supervision for other commands.
The supervisor samples the process tree and its own PSS every 50 ms, using
summed RSS as a conservative upper bound when PSS is unavailable. Exceeding
the budget terminates the owned tree. Sampling permits allocation overshoot;
this is not a hard allocation ceiling. Worker counts and received-pack caches
also adapt to the budget. Ordinary commands keep their direct startup path
when the variable is unset.

* Design

- =lisp/ngit-native.el= — file reads via =syscall-direct= into reusable
  mmap buffers, zlib inflate via libz =uncompress2= through the nl-ffi dlsym
  path (compression is in the approved FFI scope).  Linux x86_64 only.
- =lisp/ngit-store.el= — repository/worktree discovery, loose objects, pack
  index v2 lookup (lazy fanout, per-first-byte name slices), pack entries
  with OFS_DELTA/REF_DELTA, delta application, commit/tree parsing.
- =lisp/ngit-rev.el= — loose/packed/symbolic refs and gitrevisions subset.
- =lisp/ngit-cli.el= — commands and git-compatible formatting (C-style path
  quoting, default date format, automatic abbreviation length).
- =lisp/ngit-paths.el= — invocation-relative literal path selection and
  human status display, keeping index/tree paths relative to the root.
- =lisp/ngit-config.el= — system/global/repository config, last one wins.
- =lisp/ngit-hook.el= — runs hooks from core.hooksPath or =$GIT_DIR/hooks=
  (loaded only when the hook exists): commit, merge, sequencer, checkout,
  am, push/receive, gc --auto and reference-transaction hooks.
- =lisp/ngit-match.el= — wildmatch port, .gitignore and .gitattributes.
- =lisp/ngit-index.el= — index v2/v3/v4 and the cache-tree extension.
- =lisp/ngit-worktree.el= — lstat/open/readlink by syscall, end-of-line
  conversion (core.autocrlf, text/eol attributes, safer autocrlf).
- =lisp/ngit-changes.el= — tree/tree, tree/index (cache-tree skipping),
  index/work tree, untracked walk, submodule dirtiness, exact renames.
- =lisp/ngit-xdiff.el= — port of git's xdiff (Myers with git's heuristics,
  indent heuristic, function-name hunk headers cut at invalid UTF-8
  like diff.c sane_truncate_line).
- =lisp/ngit-status.el=, =lisp/ngit-diff.el= — status and diff output.
- =lisp/ngit-write.el= — loose objects (zlib =compress2= at
  core.looseCompression, default 1 as in git), locks, the index writer
  (byte-identical to git: version choice, v4 names, racy-clean smudge,
  TREE extension) and the cache-tree update behind write-tree and commit.
- =lisp/ngit-add.el= — add: tracked updates (stat-dirty entries are
  rehashed and invalidate their cache-tree path, as in git), untracked
  files below literal pathspecs, ignored-path errors, nested repositories
  as gitlinks.
- =lisp/ngit-log.el= — revision walking ported from revision.c (date
  queue, limit_list, TREESAME simplification, parent rewriting, topological
  sort), merge bases (commit-reach.c), pretty formats and user formats
  (pretty.c), dates, decorations, diff output for log and the history graph
  (graph.c).
- =lisp/ngit-rename.el= — diffcore-rename: exact, same-basename and
  inexact renames with diffcore-delta's span hashes and diff.renameLimit.
- =lisp/ngit-branch.el= — branch: listing with ref-filter's built-in
  format, tracking (ahead/behind, gone), creation with upstream setup,
  deletion, rename/copy with reflogs and HEAD, and config edits that follow
  config.c (set by parse-event offsets, rename/copy/remove sections).
- =lisp/ngit-show.el= — show: commits like log with --cc dense combined
  diffs for merges, annotated tags, trees and blobs.
- =lisp/ngit-tag.el= — tag: listing with filters and sorting, lightweight
  and annotated creation, -f and -d.
- =lisp/ngit-checkout.el= — work-tree writes (entry.c write_entry with
  autocrlf/eol smudge, executable bit, symlinks, gitlinks), index stat
  refresh, and checkout [REV] -- PATH.
- =lisp/ngit-reset.el= — reset --soft/--mixed/--hard and path resets; the
  new index patches only entries whose paths changed between the trees.
- =lisp/ngit-switch.el= — switch and checkout of branches: twoway merge
  carrying local changes, overwrite/untracked refusals, tracking DWIM,
  detached HEAD advice and orphaned-commit warnings.
- =lisp/ngit-rm.el= — rm (up-to-date and staged-content checks, directory
  removal) and mv (files, directories, into a directory, case-only renames).
- =lisp/ngit-restore.el= — restore of the index and/or work tree from the
  index or a revision.
- =lisp/ngit-stash.el= — stash: index/work-tree/untracked commits, the
  refs/stash reflog, list/show/apply/pop/drop/clear/branch; applying runs a
  three-way merge, and conflicts keep the stash as in git.
- =lisp/ngit-profile.el= — with =NGIT_PROFILE=1=, prints per-phase times
  to stderr.
- =ngit-main.el= loads the larger command modules only when an argument
  names their command (=ngit-main--lazy-modules=).
- =lisp/ngit-commit.el= — commit: index refresh, -a, COMMIT_EDITMSG,
  commit object, ref and reflog updates, the summary (shortstat, create/
  delete/rename/mode lines), local time zone from TZif files.
- =lisp/ngit-merge-file.el= — byte-exact port of xdiff/xmerge.c and the
  merge-file command.  =lisp/ngit-merge-tree.el= merges three trees with
  file rename reconciliation from =lisp/ngit-merge-rename.el=;
  =lisp/ngit-merge.el= runs merge and its state files;
  =lisp/ngit-sequencer.el= replays commits for cherry-pick, revert and the
  merge backend of rebase.
- =lisp/ngit-objects.el=, =lisp/ngit-pack.el=, =lisp/ngit-maint.el=,
  =lisp/ngit-fsck.el= — object enumeration and reachability, pack writing
  and indexing, repack/gc/prune/pack-refs/reflog, and fsck.
- =lisp/ngit-remote.el= (init, remotes), =lisp/ngit-transport.el= (smart
  protocol client, fetch/pull/push and clone) with
  =ngit-transport-process.el= (local and ssh subprocesses),
  =ngit-transport-index.el= (received-pack indexing),
  =ngit-transport-delta.el= and =ngit-transport-kernel.el= (delta
  application compiled to native code once per process) and
  =ngit-transport-checkout.el= (parallel initial checkout).
  =ngit-transport-memory.el= plans worker/cache allowances and
  =tools/transport-memory.py= supervises owned descendants using Linux
  subreaping and pidfd signals.
- =lisp/ngit-blame.el=, =lisp/ngit-grep.el=, =lisp/ngit-describe.el= (with
  name-rev, shortlog and rev-list), =lisp/ngit-lines.el= (line scans).
- =lisp/ngit-patch.el= (format-patch, apply, am), =lisp/ngit-clean.el=,
  =lisp/ngit-worktree-cmd.el=, =lisp/ngit-config-cmd.el= (config writes)
  and =lisp/ngit-bisect.el=.

** NeLisp performance notes

The interpreter costs tens of microseconds per primitive call, and several
primitives scale with the whole string length.  Measured on 2026-10-17:
=string-search= with a START argument ~3–25 ms, =format= ~0.7 ms, a
regexp match ~1–17 ms, an =aref= a few µs.  Hot paths therefore use =aref=
loops and lookup tables instead of =string-search=, =format= and regexps.
=puthash= with a vector key in an =eq= table costs ~1 ms (an integer key
~13 µs), so per-entry sets are keyed by index positions.  =maphash= costs
tens of milliseconds even on a small table, so tables keep side lists.

The faster NeLisp build (=~/.local/bin/nelisp= from the anvil build) makes
=string-search= native (proportional to the string length per call), which
ngit uses for tree lookups; the older =target/nelisp= runs ngit about four
times slower.  Objects are found through the loose listing of their
=objects/XX= directory first and then the packs in most-recently-hit
order, abbreviations follow find_unique_abbrev with one binary search per
pack, and zlib's =uncompress2= is called through =ptr-call= with an address
resolved once.

** Byte code

NeLisp spends 20–40 ms on the first call of each function loaded from
source, which dominated every ngit command.  =tools/build-elc.sh= compiles
=lisp/*.el= with the host GNU Emacs (=EMACS=, default =emacs=) through
=tools/compile.el=; NeLisp runs the byte code and commands become two to
four times faster.  =ngit-main.el= uses the =.elc= files only while
=lisp/.elc-stamp= is newer than every source (any change rebuilds all
modules) and falls back to the sources otherwise or with =NGIT_NO_ELC=1=.
The test scripts call =tools/build-elc.sh= first; without Emacs they run
from source.  =tools/compile.el= works around three NeLisp limits found on
2026-10-20: the Bsubstring opcode rejects vectors, and the reader reads
neither =#@= lazy docstrings nor =#N==/=#N#= labels.  =NGIT_PROFILE_FNS=
(with =NGIT_PROFILE=1=) adds space-separated function names to the
profiled phases.

* Not supported yet

HTTP(S) and git:// transports, shallow/partial/single-branch clones,
template copying, =--force-if-includes= pushes,
push.default=matching/nothing, multi-head pulls, submodules (beyond
gitlink entries), directory rename inference in merges, strategy-specific
rename thresholds, octopus merges, custom merge
drivers, interactive rebase (and its hooks), rerere, =--fix-thin=, git's delta search depth
(new deltas are limited to 4 KiB targets and 32 KiB per run; pack
compression defaults to level 1), blame -M/-C, grep -P, name-rev --all,
mailmap, binary patches and general MIME mail in am/apply.

Alternates, multi-pack-index, reftable, split or sparse
indexes, SHA-256 repositories, magic pathspecs (log takes literal and glob pathspecs), copy detection
and inexact renames outside log and merge (status, diff and commit summaries
detect exact renames only), commit
signing, an editor for commit messages (use -m or -F), commit with
paths, guessed identities (user.name and user.email or the GIT_*
variables must be set), date formats other than raw and ISO 8601 in
GIT_*_DATE, index.version for new indexes, =-uall=/ignored listings, include/includeIf in config,
custom attribute macros and diff drivers, =diff --relative= and comprehensive
subdirectory path handling outside status/diff/add/restore/log/show/grep/blame/ls-tree,
log's --follow, -L, -m/--cc (show has the default --cc), --simplify-merges,
--ancestry-path, --boundary, --left-right, notes, mailmap, %(trailers),
%w(), padding and color placeholders, --date=relative/human and
approximate dates (--since takes timestamps and ISO dates with a time),
branch --format, --column, --edit-description, -t inherit and colors,
tag signing/--format/--column/--edit, reset --merge/--keep/-p,
checkout/switch --merge/--conflict/-p/--overlay options and sparse
checkouts, restore -p/--ours/--theirs, rm/mv --sparse, stash -p/--all/--staged.
