#+TITLE: ngit daily use: the README "Not supported yet" list

Requested on 2026-10-25 ("implement the unsupported parts quickly"), which
overrides the earlier exclusion of editor/TTY-driven commands, signing and
submodules.  Baseline: 5db0c7f.  The denominator is README.org's "Not
supported yet" list as of 5db0c7f plus the protocol-v2 follow-ups, one item
per line below, each tagged with its wave.  Wave A covers daily commands,
wave B history rewriting and merge machinery, wave C TTY-interactive
commands, signing, submodules and shallow/partial transfers; items tagged
"infra" are storage or transport internals with no daily-use effect and are
not planned.  Stages and criteria are added per wave before its lanes start;
stage SA's criteria were defined before implementation (SA.10-SA.14 before
the third wave-A lane started).
Criteria SA.16-SA.21 were added at integration (calibration and regression
split to fit the 600 s limit; the apply engine suite after three review
rounds).  apply/am divergences that exist at 60924e0 and are reachable only
through apply --cached, am or mail parsing are kept as failing cases in the
ungraded mode `sh test/apply-gen.sh deferred` and listed in README.
On 2026-10-26 the user ended ngit development after wave A: waves B and C
are not planned and their items stay in README's "Not supported yet" list.
On 2026-10-27 the user reopened defect fixes only: the deferred apply/am
divergences are tracked in tools/ai/git-apply-deferred-progress.org.

Each suite compares ngit with Git 2.47.3 on fresh fixtures (output, exit
code, repository state) and reports exact comparisons and intended
differences separately; an intended difference is a named diagnostic or
security divergence and never counts as exact.  The verifier enforces a
floor per mode, Git-vs-Git calibration and a red 5db0c7f baseline.
